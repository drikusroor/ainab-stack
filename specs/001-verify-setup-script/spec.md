# Feature Specification: Verify Setup Script Idempotency and Correctness

**Feature Branch**: `001-verify-setup-script`
**Created**: 2026-01-01
**Status**: Draft
**Input**: User description: "This project is about configuring a flawless idempotent setup script for an empty shell greenfield next.js application. A bit is already there so please infer the stack. Other than that, we need ways to verify that the script always works and configures a project correctly with the right tools and dependencies and can lint, test, check types, and build without any errors or as little errors as possible."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Verify Fresh Setup (Priority: P1)

As a developer, I want to run a verification suite that executes the setup script on a fresh directory and validates the generated project so that I can be confident the scaffolder works correctly.

**Why this priority**: Essential for ensuring the core function of the tool works.

**Independent Test**: Run the verification tool pointing to a clean directory; it should succeed and report all checks passed.

**Acceptance Scenarios**:

1.  **Given** a clean environment, **When** the verification suite runs the setup script, **Then** the script completes with exit code 0.
2.  **Given** the setup script has completed, **When** the suite runs `bun run build` in the generated project, **Then** the build completes without error.
3.  **Given** the generated project, **When** the suite runs `bun run lint` (Biome), **Then** no linting errors are reported.
4.  **Given** the generated project, **When** the suite runs type checking (tsc), **Then** no type errors are reported.

---

### User Story 2 - Verify Idempotency (Priority: P2)

As a developer, I want to ensure that running the setup script multiple times on the same project does not break it or duplicate configuration, so that I can safely re-run the tool to update dependencies or configurations.

**Why this priority**: "Flawless idempotent setup" is a key requirement.

**Independent Test**: Run the verification tool with an "idempotency check" flag or mode; it runs setup twice and asserts success.

**Acceptance Scenarios**:

1.  **Given** a project already generated by the setup script, **When** the setup script is run again on the same directory, **Then** it completes successfully without error.
2.  **Given** a re-run of the setup script, **When** `bun run build` is run, **Then** the project still builds successfully.
3.  **Given** a re-run of the setup script, **When** checking file contents, **Then** no critical configuration files (e.g., `package.json`, `biome.json`) are corrupted or duplicated invalidly.

---

### User Story 3 - Comprehensive Stack Verification (Priority: P3)

As a maintainer, I want the verification suite to check for the presence and valid configuration of all core stack components (NextAuth, Drizzle, Tailwind, Shadcn, TanStack Query) so that I know the specific "Ainab Stack" is fully provisioned.

**Why this priority**: Ensures the "opinionated" part of the stack is correctly enforced.

**Independent Test**: The verification suite reports specific checks for each component.

**Acceptance Scenarios**:

1.  **Given** a generated project, **When** verified, **Then** it confirms `next-auth` is installed and configuration files exist.
2.  **Given** a generated project, **When** verified, **Then** it confirms `drizzle-orm` is installed and schema files exist.
3.  **Given** a generated project, **When** verified, **Then** it confirms `tailwindcss` and `biome` are configured and working.

### Edge Cases

-   **Network Failure**: What happens if dependencies cannot be fetched during setup? (Should fail gracefully with clear error)
-   **Permissions**: How does the system handle non-writable directories?
-   **Timeout**: What if the setup script hangs indefinitely? (Should enforce a timeout)
-   **Dirty Directory**: What happens if the directory contains conflicting files that are not part of the generated project?

## Requirements *(mandatory)*

### Functional Requirements

-   **FR-001**: The verification system MUST execute the project's setup script (`setup.ts`) in a temporary or specified directory.
-   **FR-002**: The verification system MUST validate that the setup script is idempotent (can be run multiple times without failure).
-   **FR-003**: The verification system MUST run the generated project's build command and fail if it errors.
-   **FR-004**: The verification system MUST run the generated project's linting command (Biome) and fail if it errors.
-   **FR-005**: The verification system MUST run the generated project's type checking (TypeScript) and fail if it errors.
-   **FR-006**: The verification system MUST check for the existence of critical configuration files for: Next.js, Tailwind, Biome, Drizzle, NextAuth, and TanStack Query.
-   **FR-007**: The verification system MUST provide clear output indicating which checks passed and which failed.

### Assumptions

-   The setup script is runnable via `bun run setup.ts` (or similar).
-   The environment has `bun` installed.
-   Internet access is available for fetching dependencies during setup.

## Success Criteria *(mandatory)*

### Measurable Outcomes

-   **SC-001**: Verification suite completes a full run (setup + build + lint + typecheck) in under 5 minutes (assuming average network speed).
-   **SC-002**: 100% of the defined stack components (Next.js, Tailwind, etc.) are verified for presence.
-   **SC-003**: The setup script can be run 3 consecutive times on the same directory with 100% success rate (exit code 0).
-   **SC-004**: The generated project passes its standard build process with 0 errors.
